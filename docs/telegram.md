# Заявки сайта → Telegram

Бот: **@SeflCheck_lead_bot** (написание предоставлено владельцем).
Бот уже добавлен в группу. Он используется только для уведомлений с форм сайта.
Username не участвует в отправке: Telegram определяет бота по токену.

## Переменные для разработчика

Шаблон — `.env.example`. Значения задаются только на сервере:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Ключ созданного бота, хранится у владельца |
| `TELEGRAM_CHAT_ID` | Числовой ID группы, включая начальный минус |

Файл `.env.example` ничего автоматически не подключает. На Cloudflare задать переменные окружения Pages; для локального Wrangler — `.dev.vars` (исключён из Git). На другом хостинге использовать его механизм секретов.

Для интерактивного определения ID запустить `python3 scripts/telegram-chat-id.py`: ключ вводится скрыто, скрипт показывает точное имя бота и команду для группы, затем выводит ID. Ключ не сохраняется.

Для определения ID вручную отправить в группе `/start@SeflCheck_lead_bot`, затем на доверенной машине вызвать Bot API `getUpdates` с токеном и найти `message.chat.id` именно этой группы. Не печатать полный ответ в общие логи: там могут быть сообщения и данные участников. Если уже установлен webhook, `getUpdates` недоступен: использовать полученное webhook-обновление, не удалять существующую настройку без проверки. Обновления хранятся ограниченное время — отправить свежую команду непосредственно перед проверкой.

## Сервер и формы

- Все пять форм используют `assets/lead-form.js` и `data-endpoint="/api/lead"`.
- Предпочтительно разместить обработчик на том же домене по POST `/api/lead`.
- `functions/api/lead.js` экспортирует `onRequest` для Cloudflare Pages и независимую функцию `handleLead(request, env)` с Web Request/Response API для адаптации к другому хостингу. Это не готовый Express-обработчик.
- Если адрес меняется, обновить `data-endpoint` на пяти страницах. При другом домене разработчик должен настроить CORS для конкретного домена сайта и обработку OPTIONS.
- Хостинг и адрес сервера пока не выбраны; никакой деплой этой интеграции не выполнялся.
- Webhook, команды и постоянно работающий процесс бота для исходящих уведомлений не нужны.

## Поведение

Отправляются имя, телефон, компания, раздел и адрес страницы без query-параметров и фрагмента. Успех возвращается только при HTTP-успехе и `ok: true` от Telegram. Таймаут Telegram — 8 секунд; браузера — 12 секунд. При ошибке форма сохраняет данные, кнопка становится доступной снова. Автоматических повторов нет: при потере ответа сообщение могло уже дойти, повторная отправка способна создать дубль.

Есть проверка типов, длины полей, номера телефона, лимит тела 8 КБ и поле-ловушка. **Поле-ловушка не заменяет rate limit.** До публичного запуска разработчик должен настроить ограничение запросов на `/api/lead` на уровне сервера/прокси либо общее хранилище лимитов. Очереди, гарантированного сохранения заявок и дедупликации пока нет.

## Проверка

```sh
node --test tests/lead.test.mjs
```

Тесты используют подставной Telegram API и не отправляют сообщений.
После заполнения переменных разработчик должен проверить настоящую тестовую заявку с каждой страницы, получение в нужной группе и поведение при недоступном API. Получение реальных сообщений пока не проверено. Если в группе включены темы, текущий код не выбирает отдельную тему; для этого потребуется `message_thread_id`.

Перед сбором реальных заявок заполнить оставленные в `policy.html` и `consent.html` реквизиты и согласовать размещённые тексты с ответственным за документы.
